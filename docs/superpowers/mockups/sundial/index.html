Sundial

Six proposals for Note, 2026-09-25: list motion that stays quick at any size, no zoom when the chat is tapped on a phone, a Sky theme that follows the sun, the day following the device's time zone, and a Begin working button for the moments nothing is planned. Every board is a live page; click its name to open it full size.

1 · Begin working

When no session is running and no block is on right now, the Today face offers one sun-coloured button. It asks the server for the queue of open tasks in the order the planner itself would schedule them (high urgency, then pressing, then soonest due, then oldest), and shows the first one in the arc before anything starts: what it is, why it came first, how long it is planned for. Start opens a session on it exactly as the Tasks view's own start does, so pomodoro comes on if it is enabled. Another moves to the next candidate; Not now returns to the face.

In a pomodoro session the face gains a row of round marks under the name, one per round, and the day's focused minutes so far. That is the count of sessions the timer keeps.

2 · Sky theme

A fourth theme choice next to System, Light and Dark. The page computes the sun's altitude once a minute from the date and a place, and blends the sky between four keyframes: day (the light theme as it is), golden, dusk, and night (the dark theme, with its two branches made one). Ground colours cross-fade; text and lines switch sets where the ground crosses the middle so contrast never dips. The place comes from the time zone unless the user offers their location, which stays on the device. The last palette is cached so the first paint at night is already dark.

3 · Time zone follows the device

A switch under the time zone row, on by default. On load and on focus the client reads the device's zone; when it differs from the saved one, the client saves it and says so in a toast with an Undo that turns the switch off. Nothing else changes: the server's day boundaries, nightly plan and close-the-day already run in the saved zone.

4 · List motion at any size

Three changes, none visible when the list is short.

  • Entrance as a wave, not a queue. Rows delay by their position on the page, the whole wave lasts a quarter second whatever the count, and rows below the fold are placed without animating. In two columns both columns rise together.
  • Bursts coalesce. A run of changed frames within 80 ms triggers one reload, each reload carries a sequence number so a slow older response cannot overwrite a newer one, and one FLIP pass runs from the positions before the burst.
  • No per-frame measuring. While rows fold away the list stops measuring every row on every frame; it measures once when the fold begins and once when it ends.

5 · No zoom on the phone

iOS zooms into any focused field whose text is under 16 px. The chat composer and the jot field sit at 0.92 rem, which is 14.7 px on a phone. On coarse pointers every text field goes to 1 rem, the viewport meta gains interactive-widget=resizes-content so the keyboard pushes the composer up instead of covering it, and buttons get touch-action: manipulation so a fast double tap never zooms. Nothing is mocked because nothing looks different.

What is not in these boards

  • Light mode already exists as a choice; Sky reuses it as its day keyframe. The only light-mode change is that the two dark branches (chosen and system) get the same sky.
  • Rows removed by another device still vanish without a fold. A fold needs the old row kept around after the data drops it; it is a separate change if wanted.
